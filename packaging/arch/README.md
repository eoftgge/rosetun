# rosetun-bin

The AUR recipe installs the release archive without compiling it. sing-box and
Xray are bundled at the versions the helper verifies, under `/usr/lib/rosetun`.
The archive is repackaged from the very same Debian build, with its licenses
moved to `/usr/share/licenses/rosetun` and the adjacent GUI symlink adjusted.
It contains no `DEBIAN` maintainer scripts. Root ownership and fixed tar order,
timestamps and gzip headers make archive creation reproducible.

Runtime validation on Arch is pending. It requires manual checks without an
Arch VM matrix; automated system checks currently use Debian 13 only. The
release workflow has a separate packaging-only Arch container check, pinned
by image digest; it builds with makepkg and runs namcap without installing
Rosetun or starting its services. The dependency list maps the Debian GUI
dlopen libraries plus glibc and gcc-libs to Arch packages. Review namcap's
dependency diagnostics and `ldd /usr/lib/rosetun/{rosetun,rosetun-gui,rosetun-helper-privileged}`
on the owner's Arch system before publishing.

## Prepare and publish

The initial checksum deliberately blocks builds until 0.5.0 has been published.
Never replace it with SKIP or an invented checksum. On Arch, from the repository
root, after the release:

```sh
bash tools/arch/update-pkgbuild.sh v0.5.0
cd packaging/arch
makepkg --printsrcinfo > .SRCINFO
makepkg -s
namcap PKGBUILD rosetun-bin-*.pkg.tar.zst
```

`.SRCINFO` is generated by makepkg, not maintained by hand. It is not committed
in the initial recipe because makepkg is unavailable on the development host
and the release checksum does not exist yet. The updater fetches the exact
asset entry from the release's SHA256SUMS.txt and generates it before replacing
the recipe. Run the same updater with the next release tag; it resets pkgrel
to 1. Review the changes and the archive provenance before uploading.

Create an account at https://aur.archlinux.org/register and add an SSH public
key to its account settings. For example:

```sh
ssh-keygen -t ed25519 -f ~/.ssh/aur -C aur
cat ~/.ssh/aur.pub
```

Configure `Host aur.archlinux.org`, `User aur`, `IdentityFile ~/.ssh/aur` in
`~/.ssh/config`, then `ssh -T aur@aur.archlinux.org`. Verify the server host
key using https://wiki.archlinux.org/title/AUR_submission_guidelines.
From the Rosetun repository root, first publication:

```sh
git clone ssh://aur@aur.archlinux.org/rosetun-bin.git ../rosetun-bin-aur
cp packaging/arch/{PKGBUILD,.SRCINFO,rosetun-bin.install,rosetun-remove.hook,pre-remove.sh} ../rosetun-bin-aur/
cd ../rosetun-bin-aur
git add PKGBUILD .SRCINFO rosetun-bin.install rosetun-remove.hook pre-remove.sh
git commit -S -m 'packaging: Publish rosetun-bin 0.5.0' -m 'Install the published Linux archive with pinned engines and guarded Lockdown removal.'
git push
```

For subsequent releases, use `git -C ../rosetun-bin-aur pull --ff-only`, copy
the same files, and commit and push there. The updater only prints commands;
it never clones, commits or pushes to AUR.

## Version order

Keep stable `0.5.0` unchanged. Map `0.6.0-beta.1` to `pkgver=0.6.0beta1`
while `_release=0.6.0-beta.1` preserves the exact GitHub tag and asset name.
The updater performs this conversion and checks the order using vercmp:

```sh
vercmp 0.6.0beta1 0.6.0       # -1
vercmp 0.6.0beta2 0.6.0beta10 # -1
```

See https://man.archlinux.org/man/vercmp.8.en.

## Services and removal

The install script only prints installation and upgrade instructions. Arch's
systemd hooks create the sysusers accounts and reload the manager after unit
changes. No script enables services or restarts them on upgrade. The root-only
`rosetun-helper-privileged --restart-for-upgrade` marks the stop before calling
`/usr/bin/systemctl` with an empty environment. This matches the existing
Debian upgrade protocol; Debian retains its policy-aware prerm/postinst flow.
The command waits for Type=notify readiness and a matching-version IPC status
response. Concurrent requests are rejected with a nonblocking file lock outside
the service's runtime directory. A failed restart never resets protection.

An `.install` failure does not guarantee that pacman aborts deletion. Therefore
the installed `10-rosetun-remove.hook` runs the firewall reset in PreTransaction
with AbortOnFail, before the recovery executable can disappear. Do not bypass
the hook. `pre_remove` repeats the reset safely. See
https://man.archlinux.org/man/alpm-hooks.5.en and
https://devblog.archlinux.page/2026/on-scripts-and-hooks/.

## Manual checks

After the owner publishes the recipe, on an Arch x86_64 system using systemd
and cgroup v2:

```sh
git clone https://aur.archlinux.org/rosetun-bin.git
cd rosetun-bin
makepkg -si
sudo systemctl enable --now rosetun-helper rosetun-lockdown
sudo usermod -aG rosetun "$USER"
sudo reboot
```

After reboot, `systemctl is-active rosetun-helper rosetun-lockdown` must report
both active, `id -nG` must include rosetun, and `rosetun status` must answer.
Open `rosetun-gui`, import an owner's test subscription, enable the kill switch,
connect and verify tunnel traffic. Direct traffic bound to the physical interface
must fail. Keep probing it during the next package installation and both calls:

```sh
sudo pacman -U ./rosetun-bin-<next-version>-1-x86_64.pkg.tar.zst
sudo rosetun-helper-privileged --restart-for-upgrade
sudo rosetun-helper-privileged --restart-for-upgrade
rosetun status
rosetun connect
```

Status before reconnect must report the network held closed; no direct probe
may succeed. A GUI may reconnect automatically, in which case confirm its
connection and the continuing direct block. Also test an idle unprotected
restart, which must report that the network was not held closed.

Enable Lockdown and remove the package:

```sh
sudo rosetun lockdown on
sudo pacman -R rosetun-bin
```

The hook must release Lockdown before files disappear. Separately, simulate a
reset failure in a disposable Arch environment: removal must abort with the
helper still installed. To recover before retrying:

```sh
sudo rosetun reset-firewall
sudo pacman -R rosetun-bin
```

Keep `journalctl -b -u rosetun-helper`, the pacman transcript and the direct
probe counters if any result differs. Do not publish personal node details.

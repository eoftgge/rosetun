Help and FAQ

Install and connect

  1. Download and verify the installer. Windows 11 x64 is required. Windows 10 is untested.
  2. Run the installer and approve the administrator prompt. The installer is unsigned: if SmartScreen shows “Windows protected your PC”, after verifying the file choose “More info”, then “Run anyway”.
  3. Open Rosetun and add a subscription URL from your provider. Rosetun does not supply VPN servers.
  4. Select a server and connect. Rules choose what uses the VPN, connects directly or is blocked.

Choose an installation folder outside user profiles that ordinary users cannot modify.

Debian 13

Linux is new in this beta: Debian 13, amd64, KDE Plasma first and GNOME in part. Download the package from Releases and verify it: 

sha256sum --check --ignore-missing SHA256SUMS.txt
gh attestation verify rosetun_VERSION_amd64.deb --repo eoftgge/rosetun

Install it and add yourself to the group that may reach the service:

sudo apt install ./rosetun_VERSION_amd64.deb
sudo usermod -aG rosetun "$USER"

Then restart the computer: logging out is not enough.

Linux has no rules by program, file dialogs or Collect report yet. A connection with a rule by program is refused. Update, remove, purge.

System proxy

Connection mode in Settings → Connection chooses how traffic reaches the VPN. TUN takes all of this computer's traffic. System proxy starts a local proxy and points your desktop's proxy settings at it, for when TUN gets in the way of another VPN, an anti-cheat or an antivirus, or when you only need the browser.

  • Only programs that use the system proxy go through the VPN: browsers and most applications. Games, many console programs and Windows services (WinHTTP stays as it is) do not, and without the kill switch they go direct, their DNS included.
  • The kill switch here is strict: everything that does not use the proxy stays without network, while you are connected too.
  • Access from the local network lets a phone or a TV on your network use the proxy. Settings shows the address to enter. Only your own networks get in; under Lockdown it also needs Local network.
  • Your own proxy settings come back when you disconnect, quit or change the mode, and at the next start after a crash. If you changed them yourself meanwhile, they stay.
  • On Linux the settings are changed on KDE Plasma and GNOME. On other desktops Rosetun shows the address to enter in your system settings. Point console programs at the proxy yourself.

Lockdown and restoring network access

Lockdown is experimental. It blocks internet access outside the tunnel, even without a connection and after a restart. Turning it on or off in Settings → Connection requires confirmation and administrator rights: UAC on Windows, polkit on Linux. The kill switch stays on while Lockdown is enabled.

If there is no network access and Rosetun will not open, open Windows Terminal as administrator and run this, with your own folder if you chose another: 

& 'C:\Program Files\Rosetun\rosetun.exe' reset-firewall

On Linux:

sudo rosetun reset-firewall

This removes Lockdown without a running service. Once Lockdown is removed, direct internet access becomes possible. Uninstalling Rosetun also removes Lockdown.

For Wi-Fi with a sign-in page, temporarily turn off Lockdown, sign in or fix the clock, connect and enable Lockdown again. Lockdown cuts off Hyper-V networking; WSL2, Docker Desktop, Windows Sandbox and the mobile hotspot can also lose access, and on Linux virtual machines and containers. Turn off Lockdown while you need them.

Windows 10, third-party firewalls, antivirus software, hibernation and sleep on real hardware are untested. The kill switch remains the primary protection. Lockdown does not protect against malware running under your account.

What stays closed

The window and rosetun status show the protection in place. The main difference between the systems: on Windows a crash of the service opens the network unless Lockdown is on; on Linux the kill switch keeps it closed until you connect or run rosetun open-network. An update keeps the network closed on both while the kill switch is on. The table for each event.

Local network

Local network in Settings → Connection lets programs reach devices on your network past the tunnel. On Windows it opens only your own network, and Private networks behind the router adds the other private ranges. On Linux the firewall opens every private range. Details and limits.

Privacy

There is no telemetry and no account. Rosetun contacts your provider, servers, DNS, lists, GitHub and network check services. The device ID sent to a provider is a hash for that provider's host, not your system's ID. Every request and what it carries.

Frequently asked questions

A website will not open after connecting

Restart the browser: it has its own DNS cache, separate from the system's.

Another VPN or zapret interferes with the connection

Disconnect the other VPN in TUN mode and retry. If you use zapret, exclude your VPN server addresses in its settings.

The network is closed after an update or a crash

Connect, or open it with Open network on the connection screen or rosetun open-network. Without a working service, use reset-firewall as above.

Linux: no access to the Rosetun service

Press Add me, or run sudo usermod -aG rosetun "$USER", and restart the computer. Logging out is not enough.

Linux: KDE programs do not use the proxy

Check that ~/.config/kioslaverc has ProxyType=1 and that XDG_CURRENT_DESKTOP contains KDE; otherwise enter the address Rosetun shows yourself. Restart programs that are not KDE's or Chromium.

Where do I start troubleshooting?

Open Settings → Service and logs → System check. It checks the clock, other VPNs and DNS substitution, and on Windows the system proxy and packet interception. It runs automatically after a failed connection. It changes nothing but does make network requests.

What does “No network connection” mean?

Check the system's network. With reconnect on disconnect enabled, Rosetun waits for the network to return while the kill switch blocks traffic as long as the service is running.

The installer reports access to a protected folder

If ordinary users can modify the Rosetun folder, uninstall and install again. Do not grant access to the service folder through the “Continue” button in Explorer.

Collect a report

On Windows, in Settings → Service and logs, select “Collect report”. The text file contains versions, settings without secrets, connection state, system checks and logs. The system check makes network requests.

Rosetun removes IP addresses, URLs, domains, email addresses, keys, passwords, server, subscription, list and rule set names, and your Windows account name. Review the file yourself before sharing.

Linux has no such report yet. Attach rosetun status and the logs listed in the README, and remove addresses, links and names by hand first.

In Issues, attach the report, steps to reproduce, expected behavior and error text. Do not attach subscription URLs or configurations containing secrets. Report vulnerabilities privately using the footer link.

Update or uninstall

Rosetun offers new versions but never downloads or installs them itself. Download the new installer or package from Releases, verify it and run it. With the kill switch on, the network stays closed through the update. When the settings format changes, Rosetun keeps a copy of the previous file alongside it; this copy also contains subscription URLs.

On Windows, uninstall Rosetun through Windows apps. Settings in %APPDATA%\Rosetun are kept by default; the uninstaller can remove settings, subscriptions and rules.

ROSETUN ДЛЯ ВАШИХ ПОЛЬЗОВАТЕЛЕЙ

Для провайдеров

Обычная подписка. Одна кнопка для добавления.

Кнопка на вашем сайте

Формат: rosetun://add/<ссылка подписки>#имя. Ссылка HTTP(S) может быть сырой или целиком percent-encoded. Имя необязательно, декодируется из percent-encoding и ограничивается 64 символами. Вся ссылка: не больше 8192 байт. 

<a href="rosetun://add/https%3A%2F%2Fprovider.example%2Fsubscription%2Fdemo#Example">Добавить в Rosetun</a>

После установки Rosetun система открывает такую ссылку в приложении: на Windows через схему, которую регистрирует установщик, на Linux через обработчик .desktop из пакета (x-scheme-handler/rosetun). Следующий запуск передаёт ссылку работающему Rosetun по каналу, который может открыть только учётная запись пользователя: именованный канал на Windows, сокет в $XDG_RUNTIME_DIR на Linux. Пользователь видит окно добавления с хостом провайдера. Загрузка и добавление начинаются только после подтверждения. Если подписка уже есть, открывается её карточка; ссылка не заменяет уже открытый диалог.

Используйте HTTPS. В HTTP-ссылке токен передаётся без шифрования. В сыром HTML экранируйте амперсанды как &amp;.

Форматы и серверы

Список URI по одному на строку, обычный или base64. Xray JSON: объект конфигурации или массив конфигураций; из каждой берётся поддерживаемый outbound с тегом proxy, иначе первый поддерживаемый. sing-box JSON: объект с outbounds; служебные selector, urltest, direct, block и dns пропускаются. Это импорт серверов, а не всей конфигурации маршрутизации.

VLESS, VMess, Trojan, Shadowsocks, Hysteria2. TCP, WebSocket, gRPC, HTTPUpgrade; XHTTP (SplitHTTP) через Xray. Без шифрования транспорта, TLS и REALITY. Для Hysteria2: QUIC поверх UDP, Salamander и смена портов.

Не поддерживаются: Clash YAML, зашифрованные ссылки Happ, XHTTP с отдельным сервером загрузки, mKCP, QUIC-транспорт для TCP-протоколов, HTTP/2, шифрование VLESS и плагины Shadowsocks. Неподдерживаемые узлы пропускаются; причины доступны в отчёте импорта в карточке. Если подходящих узлов нет, добавление завершается ошибкой. Ответ подписки ограничен 5 МиБ после распаковки.

Заголовки ответа

Заголовок Обработка
subscription-userinfo upload и download: байты; total: лимит в байтах; expire: Unix-время в секундах. Нулевые total и expire означают отсутствие лимита и срока. Трафик и срок видны в карточке подписки.
profile-title Название подписки, до 128 символов. Обычный текст или base64:…; используется при добавлении, если пользователь не задал имя.
content-disposition Резервное название из filename или UTF-8 filename*. До 128 символов; profile-title имеет приоритет.
profile-update-interval Целое число часов. Автообновление ограничивает интервал диапазоном 1–168 часов; по умолчанию 12 часов. Пользователь может выключить автообновление.
support-url / profile-web-page-url Ссылки поддержки и личного кабинета в карточке. Только HTTP(S), текст ограничен 2048 символами перед проверкой URL.
announce Объявление в карточке подписки: обычный текст или base64:…, до 1000 символов.
x-hwid-max-devices-reached / x-hwid-not-supported / x-hwid-limit Значение true без учёта регистра останавливает разбор с ошибкой ограничения устройства; announce передаётся вместе с ошибкой.

У отображаемого текста удаляются управляющие символы и знаки направления текста. Некорректные значения метаданных игнорируются. Эти же метаданные читаются из строк # ключ: значение списка ссылок. Заголовок routing не обрабатывается и не устанавливает правила.

Что получает ваш сервер

По умолчанию User-Agent: Rosetun/<версия>; пользователь может задать другой User-Agent. При включённом «Отправлять ID устройства» запрос добавляет x-hwid, x-device-os, x-ver-os, x-device-model. Если сведения об устройстве получить не удалось, запрос идёт без них.

Отправка включена по умолчанию и выключается для каждой подписки, в CLI через --no-hwid. Новые подписки получают ID, свой для каждого хоста сервера подписок: путь, токен и порт его не меняют. Разные хосты получают разные ID. У подписок, добавленных до 0.4, сохраняется прежний общий ID. Версия ОС и модель ограничены 64 печатными ASCII-символами; остальные символы заменяются на ?.

На Windows x-device-os равен Windows, ID получается из MachineGuid, версия из реестра, модель из BIOS. На Linux x-device-os равен Linux, ID получается из /etc/machine-id, версия из PRETTY_NAME в os-release, модель из /sys/class/dmi/id/product_name. Если система модели не даёт, отправляется PC. Сам системный идентификатор не отправляется, только его хеш.

Проверьте подписку

  1. Установите текущий выпуск и откройте кнопку добавления.
  2. Проверьте хост, подтвердите добавление и проверьте серверы, название, трафик, срок и ссылки карточки.
  3. Обновите подписку. При ошибке откройте её карточку и подробности отчёта импорта.
  4. Для воспроизведения подготовьте обезличенный пример ответа и заголовков. Укажите версию Rosetun, ожидаемое поведение и текст ошибки. Не отправляйте токен, HWID, настоящие адреса или ключи.

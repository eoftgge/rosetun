Стабильная версия для Windows: 0.4. Linux и перечисленные ниже изменения доступны с предварительной 0.5; стабильная 0.5 ещё не вышла. Точное поведение 0.4 описано в документации 0.4.

Подписки и серверы

С 0.5: собственные прокси HTTP/HTTPS/SOCKS5 и фрагментация TLS.

  • Подписки провайдеров: списки ссылок в обычном виде или в base64, Xray JSON и sing-box JSON. Подписку можно добавить по ссылке, по QR-коду (из файла, из буфера обмена или с части экрана на Windows, из буфера обмена на Linux) или ссылкой rosetun:// со страницы провайдера.
  • Собственные прокси HTTP, HTTPS и SOCKS5 на вкладке Прокси окна добавления.
  • Отправлять ID устройства (HWID) включено по умолчанию: панели с лимитом устройств без него отвечают «подписка не найдена». Выключается для каждой подписки в окне добавления (--no-hwid в CLI). См. Приватность и сетевые обращения.
  • Серверы VLESS, VMess, Trojan, Shadowsocks и Hysteria2 (обфускация Salamander и смена портов); транспорты TCP, WebSocket, gRPC и HTTPUpgrade для протоколов на TCP, а также XHTTP (SplitHTTP) через Xray; режимы без шифрования транспорта, TLS и Reality. Hysteria2 работает по QUIC поверх UDP. Пока не поддерживаются, такие серверы пропускаются: XHTTP с отдельным сервером загрузки, транспорты mKCP, QUIC и HTTP/2, шифрование VLESS, плагины Shadowsocks и другие протоколы.
  • Подключение через Xray (Настройки → Дополнительно): Автоматически (по умолчанию): Xray для серверов VLESS с REALITY и для XHTTP, sing-box для остальных; Без Xray: sing-box сам соединяется со всеми серверами; Xray для всех серверов: через Xray идут все поддерживаемые серверы, кроме Hysteria2. В списке серверов отмечены те, что идут через Xray.
  • Фрагментация TLS (Настройки → Дополнительно): дробит первые пакеты к серверу, что помогает, если оператор режет подключение по первому пакету. Серверы, которые ведёт Xray, при включённой настройке идут через него; на экране подключения видно, применяется ли она к текущему серверу.
  • DNS через туннель с настраиваемым DNS-over-HTTPS-резолвером.
  • Проверки серверов: пинг TCP (время соединения) и проверка URL с запросом через каждый сервер, в том числе при подключённом туннеле, через ту же цепочку, что и подключение.

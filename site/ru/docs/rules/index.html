Программы на Linux
  • Правила маршрутизации для программ, сайтов, IP-адресов и подсетей и списков, Быстрые шаблоны и действия Через VPN, Напрямую и Блокировать.
  • Направления: правило может вести свой трафик через другую страну или конкретный узел, а остальное идёт через сервер с главного экрана. Выбор страны или узла в правиле создаёт направление во вкладке Направления; там можно сменить его узел и включить запасной: любой узел той же страны. Если узел направления пропал, его правила блокируют трафик и никогда не идут напрямую.
  • Списки: GeoIP и GeoSite (файлы Xray .dat, наборы правил sing-box) и свои текстовые списки из файла или по ссылке. Список по ссылке скачивается заново, только если он изменился (ETag / Last-Modified).
  • Отмена: Ctrl+Z отменяет изменения во вкладке «Правила» по шагам, Вернуть возвращает правила, применённые к подключению, а Del удаляет выделенное правило без вопроса.
  • Временные правила: добавьте правило только до отключения; оно применяется сразу и никогда не сохраняется.
  • Соединения на вкладке «Трафик»: при подключении видно, куда программы соединяются прямо сейчас, по программам, каким маршрутом пошло каждое соединение и почему (какое правило, список или правило по умолчанию). Оттуда же можно создать правило или закрыть соединение. Список хранится только в памяти, только для учётной записи, которая подключилась, и очищается при отключении; на диск и в журнал он не попадает.

Программы на Linux

Правила по программам на Linux имеют цену. Чтобы найти программу соединения, sing-box читает процессы всех учётных записей, поэтому сеанс с включённым правилом по программе даёт своему ядру CAP_SYS_PTRACE и CAP_DAC_READ_SEARCH: почти root для того, кто захватит ядро. Без такого правила у ядра нет ни того, ни другого. Там, где служба не может их дать (например, вне своего юнита systemd), подключение с таким правилом отклоняется с указанием причины.

Известная ошибка sing-box на Linux: соединение иногда приписывается не той программе (SagerNet/sing-box#4501, открыта; на Windows не относится). Поэтому правило «Напрямую» для программы может изредка пропустить мимо туннеля чужое соединение, и при включённом kill switch тоже: ядру kill switch выход разрешает. Соединение, программа которого не найдена, не подходит ни под одно правило по программе и идёт по следующим правилам. Если это важно, используйте правила по сайтам и IP, а по умолчанию оставьте «Через VPN» без правил «Напрямую» по программам.

Экспорт и импорт

На вкладке «Правила» откройте список наборов («Основной»). Выберите экспорт всех или выделенных правил; команды импорта находятся в том же списке. Скопируйте документ в буфер обмена или сохраните JSON-файл на Windows. На Linux пока доступен только буфер обмена. Для импорта откройте то же меню, проверьте правила и выберите «Добавить» или «Заменить». Дубликаты пропускаются. Весь импорт, включая правило по умолчанию и ссылки на списки, отменяется одним Ctrl+Z.

Перед импортом показаны назначения, дубликаты, неверные и выключенные правила, недоступные серверы. Правило по умолчанию меняется только после отдельной отметки. Для широких правил «Напрямую» есть предупреждение. Через ссылку rosetun:// импортировать правила нельзя.

Содержимое списков не передаётся. Источники по URL включаются только после подтверждения с показом хостов: ссылки могут содержать ключи доступа. Без подтверждения правила по спискам приходят выключенными с требованием выбрать список. Списки из файла требуют указанный файл, правила по ним тоже выключены. Импорт не скачивает списки.

Имена программ переводятся между Windows и Linux: firefox.exe становится firefox, регистр Linux сохраняется. Пути другой системы остаются выключенными. Сервер сопоставляется по точному имени, названию подписки и стране. Если совпадения нет или оно неоднозначно, правило получает «Через VPN» с предупреждением.

Формат обмена независим от настроек: format: "rosetun-rules", version: 1, версия приложения, исходная система, необязательное правило по умолчанию, правила и используемые списки. В документ не входят внутренние ID правил, списков и серверов, адреса и порты серверов, ключи и пароли, содержимое и хеши списков, время обновления. Ссылки на списки задаются номерами внутри документа с нуля. Неизвестные поля документа и версии отклоняются; неверные отдельные правила показываются в отчёте и пропускаются. Пределы: 4 МиБ и 10 000 правил или списков.

{
  "format": "rosetun-rules",
  "version": 1,
  "exported_by": "0.6.0",
  "system": "windows",
  "default_target": "proxy",
  "rules": [
    {"enabled": true, "matcher": {"domain": {"suffix": "example.com"}}, "target": "proxy"},
    {"enabled": true, "matcher": {"ip_cidr": "192.0.2.0/24"}, "target": "block"}
  ],
  "lists": []
}

CLI: rosetun rules export [--selected-ids 1,2] [--with-list-urls] [ФАЙЛ|-]; rosetun rules import [--replace] [--yes] ФАЙЛ|-. Экспорт без имени файла пишет в стандартный вывод. Импорт печатает предпросмотр и спрашивает перед сохранением; --yes подтверждает правила и сохраняет прежнее правило по умолчанию. Для его замены есть отдельный интерактивный вопрос. При чтении документа из стандартного ввода подтверждение читается с терминала. Храните документ со ссылками на списки как секрет и проверяйте правила «Напрямую» перед импортом.

Служба (rosetun-helper-privileged) запускает sing-box, который держит туннель, правила и DNS. Для серверов, которые идут через Xray, sing-box передаёт соединение по loopback в Xray; его тоже запускает служба, и он соединяется с сервером. Защитой владеет служба, поэтому закрытие окна её не снимает. В режиме прокси TUN нет: ядро слушает как локальный прокси.

Windows. Kill switch и замок DNS это фильтры WFP в динамическом сеансе службы, поэтому Windows снимает их, если служба остановилась или упала (fail-open). Это нужно, чтобы компьютер не остался без сети навсегда. Служба запускает sing-box из своей копии data\engines\sing-box.exe, которую могут открыть только SYSTEM и администраторы. Во время подключения sing-box ставит в брандмауэре разрешение для своего исполняемого файла, которое блокировки Rosetun не перебивают, поэтому никакая другая учётная запись не должна запускать этот файл. Копия обновляется и сверяется по SHA-256 при запуске службы; если сделать её нельзя, подключение не удаётся, а установленный sing-box.exe не запускается.

При включённом Lockdown Rosetun держит ещё и постоянные фильтры WFP в своём подуровне, которые закрывают всё мимо туннеля. Windows сохраняет их при падении службы и перезагрузке, а служба фильтрации (BFE) восстанавливает их при загрузке; время до её запуска закрывают фильтры загрузки (fail-closed). Снимаются они только выключением Lockdown, командой rosetun reset-firewall или удалением Rosetun. Удержание после обновления это тот же набор с меткой.

Linux. Брандмауэр это одна таблица nftables, inet rosetun, записанная одной транзакцией. Служба работает в cgroup с двумя листьями, helper и engines, и таблица разрешает по cgroup, а не по пути к программе или учётной записи. Ядра работают под rosetun-engine, у которой нет входа, домашней папки и других групп, и только с CAP_NET_ADMIN, CAP_NET_RAW и CAP_NET_BIND_SERVICE. Служба запускает их только из файлов, принадлежащих root. Правило polkit разрешает этой учётной записи задавать DNS интерфейса в systemd-resolved, чтобы системный DNS шёл за туннелем.

Таблица переживает службу, поэтому падение оставляет её на месте, а перезапущенная служба держит сеть закрытой. Перезагрузку компьютера она не переживает: это делает запись Lockdown в /var/lib/rosetun/lockdown, а rosetun-lockdown.service снова записывает таблицу до появления любой сети. Приложение и команда rosetun выходят под Lockdown только из своих областей systemd (scope).

Что Lockdown оставляет открытым. Ядра проходят, только когда их запускает служба, а приложение Rosetun и команда rosetun только по TCP и DNS и только без подключения, но программа под вашей учётной записью всё равно может выйти через команду rosetun, как и многими другими путями.

О Rosetun

Rosetun: VPN-клиент для Windows и Linux. sing-box держит туннель, правила и DNS; для серверов VLESS + REALITY соединение с сервером ведёт Xray за sing-box. Системная служба держит kill switch и замок DNS в брандмауэре. Правила разделяют трафик по программам, сайтам и IP-адресам, а подписки провайдеров поставляют серверы.

Молодой проект: его ведёт один разработчик с помощью ИИ-агентов, пользователей пока мало. Сообщайте о проблемах в Issues.

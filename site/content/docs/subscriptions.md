- Поддерживаются подписки со списками ссылок в обычном виде или в base64, Xray JSON и sing-box JSON. Подписку можно добавить по адресу, по QR-коду из файла или буфера обмена либо по ссылке `rosetun://` со страницы провайдера. На Windows QR-код можно прочитать и с выделенной части экрана. На Linux открытие файла использует [портал рабочего стола](../linux/).
- Собственные прокси HTTP, HTTPS и SOCKS5 на вкладке **Прокси** окна добавления.
- **Отправлять ID устройства** (HWID) включено по умолчанию: панели с лимитом устройств без него отвечают «подписка не найдена». Выключается для каждой подписки в окне добавления (`--no-hwid` в CLI). См. [Приватность и сетевые обращения](../privacy/).
- Серверы VLESS, VMess, Trojan, Shadowsocks, Hysteria2 (обфускация Salamander и смена портов), TUIC v5 и AnyTLS; транспорты TCP, WebSocket, gRPC и HTTPUpgrade для протоколов на TCP, а также XHTTP (SplitHTTP) через Xray; режимы без шифрования транспорта, TLS и Reality. Hysteria2 и TUIC v5 работают по QUIC поверх UDP, а AnyTLS по TCP поверх TLS или Reality; все три поддерживаются в ссылках (`hysteria2://`, `tuic://`, `anytls://`) и в sing-box JSON. Пока не поддерживаются, такие серверы пропускаются с указанием протокола в отчёте об обновлении: XHTTP с отдельным сервером загрузки, транспорты mKCP, QUIC и HTTP/2, шифрование VLESS, плагины Shadowsocks и другие протоколы (например, WireGuard).
- **Подключение через Xray** (Настройки → Дополнительно): **Автоматически** (по умолчанию): Xray для серверов VLESS с REALITY и для XHTTP, sing-box для остальных; **Без Xray**: sing-box сам соединяется со всеми серверами; **Xray для всех серверов**: через Xray идут все поддерживаемые серверы, кроме Hysteria2, TUIC и AnyTLS (они всегда идут через sing-box). В списке серверов отмечены те, что идут через Xray.
- **Фрагментация TLS** (Настройки → Дополнительно): дробит первые пакеты к серверу, что помогает, если оператор режет подключение по первому пакету. Серверы, которые ведёт Xray, при включённой настройке идут через него; на экране подключения видно, применяется ли она к текущему серверу.
- **DNS через туннель** с настраиваемым DNS-over-HTTPS-резолвером.
- **Проверки серверов:** пинг TCP (время соединения) и проверка URL с запросом через каждый сервер, в том числе при подключённом туннеле, через ту же цепочку, что и подключение.

## Обновления через VPN {#updates}

**Настройки → Подключение → Обновлять подписки через VPN** включено по умолчанию.
При подключении загрузка и обновление подписок идут через основной VPN-сервер,
даже если правило отправляет сайт провайдера напрямую. Это работает в TUN и
в режиме системного прокси, в приложении и в `rosetun sub update`.

Если запрос через VPN не прошёл, Rosetun показывает ошибку и не повторяет его
напрямую. Без подключения, а также при выключенной настройке используется
обычный путь; в TUN он зависит от ваших правил. Если служба недоступна и
состояние подключения неизвестно, включённая настройка останавливает обновление
с ошибкой. Выключайте её только если хотите использовать обычный путь.
Списки и проверка обновлений приложения этой настройкой не меняются.
